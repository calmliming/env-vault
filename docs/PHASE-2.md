## 2. 监听：为什么盯目录而不是盯文件

编辑器保存文件普遍是「写临时文件 → rename 覆盖」。直接监听文件路径的话，
rename 之后原来的句柄就失效了，监听器会**静默失效** —— 第一次保存能收到事件，
之后再改就再也收不到，而且不报任何错。监听父目录、按文件名过滤则不受影响。

去抖 300ms：一次保存常常触发多个事件（unlink + add，或 change 连发几次），
不去抖的话界面会闪几下。

监听层不做任何决策：它只回答「这个文件现在的哈希是什么」然后把事件抛出去。
渲染层收到后**只刷新状态，不改数据** —— §6.4 那句「任何外部修改在用户确认前
都不能被覆盖」反过来也成立：也不能在用户没确认时替他把中心记录改掉。

> ⚠️ 有五处操作会改变「有哪些文件 / 它们的基准哈希」：导入、移除、重扫、
> 以磁盘为准、以记录为准。每一处都必须调 `refreshWatchTargets()`。
> 漏掉任何一处的后果是**静默的**：监听器还活着，但拿旧哈希去比新文件。

## 3. 差异：按 (key, occurrence) 配对，不按行号

行号会因为上面插入一行注释而整体位移，那样一次无关的编辑会让所有变量看起来都变了。
按 key 配对则只有真正改了值的才亮起来。`occurrence` 必须参与配对，
否则 `DUP=first` / `DUP=second` 这种文件里的两条会互相顶掉。

**敏感项的差异两侧都是掩码。** 用户能看到「这一项变了」，看不到变成什么 ——
想看具体值要回配置表点「显示」，那条路径会留痕。差异面板是个一览视图，
把明文铺在上面等于绕过了 reveal 的审计。

## 4. 写回：四步原子替换

```
1. 并发校验（expectedHash）—— 见 §5
2. 备份原文件到 userData/backups/<路径哈希>/<时间戳>-<文件名>
3. 写同目录下的临时文件 + fsync
4. rename 覆盖目标
```

- 临时文件必须和目标**同目录**：跨设备 rename 会退化成复制+删除，就不原子了。
- 没有 fsync 的话 rename 可能先于数据落盘，掉电后得到一个长度正确但内容是零的文件。
- 备份不放原目录：`.env.bak-1234` 落在用户仓库里会被 `git status` 看见、
  可能被误提交、还会被下次扫描当成 `.env.*` 发现。
- 继承原文件的权限位：新建文件默认 `0o666&~umask`，会把原来 `0o600` 的 `.env` 放宽。
- 磁盘上不存在的 key **不追加**，原样报回去。静默追加会把中心记录里的陈旧变量
  塞回用户已经清理过的文件。

## 5. 这一刀里最值得记的一个 bug：守卫写成了摆设

`restoreFileFromCentral` 第一版是这样的：

```ts
const currentHash = currentFileHash(file.absolute_path)   // 现算
writeEnvFileAtomic(path, content, { expectedHash: currentHash })  // 拿来校验
```

看起来做了并发校验，实际上 `expectedHash` 永远等于当前值，**这个守卫不可能触发**。
验收脚本里那条「期间被外部改过就中止写入」因此一直是绿的 —— 它绿是因为
根本没进到判断，不是因为判断通过了。直到给它补上真正的并发场景
（先 diff、再从外部改文件、然后确认）才暴露出来。

修法是把 `expectedHash` 变成**调用方必须传入**的参数，语义是
「我这个决定是基于哪个版本做的」：

```
diffFile() → 返回 currentHash → 用户看着这份差异做决定 → restore(expectedHash=那个 hash)
```

主进程侧还加了一道：`expectedHash` 缺失或不是 64 位十六进制串直接拒绝，
不接受「没传就跳过校验」。

**教训**：一条从来没红过的断言，要么是代码真的对，要么是断言根本够不着它。
这两种情况在测试报告上长得一模一样。

## 6. 明确没做的：编辑单个变量

计划 §9 阶段 2 的交付里还有「搜索、筛选、**编辑**、删除、复制和掩码显示」。
搜索、筛选、复制、掩码在阶段 1 就有了，**编辑和删除还没做**。

写回的机器已经全部就位（`applyEdits` + 原子写入 + 备份 + 并发校验），
差的只是「改中心记录里的某个值」这个入口和它的 IPC。
之所以留到下一刀，是因为它会带出一串独立的决定：改完是立刻写盘还是攒着、
删除变量要不要同时从文件里删行、以及编辑态怎么和掩码共存。
和监听/差异混在一起做会让这次改动更难审。
